# ETF 估值方案档案

## 用途

本目录保存已纳入维护列表的 ETF 的**可审计估值与申赎结算方案**。每只基金都独立核对：

1. 最新招募说明书/基金合同中的申赎、现金替代、汇率和清算条款；
2. 最新交易所 PCF 的字段、最小申赎单位、成分证券和当日限额；
3. 实际交割记录所验证的结算口径。

不要因两个标的跟踪同一指数或使用同一对冲工具，就复用对方的到账日期、汇率或固定对冲股数。

## 目录与命名

按资产类型建立子目录；同一子目录内每个标的至少有三份文件：

```text
<分类>/<代码>_<名称>_更新招募说明书_<发布日期>.pdf
<分类>/<代码>_<名称>_PCF_<交易日>.xml
<分类>/<代码>_<名称>_估值方案.md
```

其中 PDF 与 XML 是用于复核的原始输入；Markdown 是程序与人工操作共同使用的解释层。新交易日的 PCF 可新增同名日期文件，但不得覆盖已经用于历史回测的原始文件。

## 统一口径

### 两个必须分开的数

```text
证券资产 = Σ(PCF 成分股数量 × 估值/成交价格 × 人民币汇率)
总篮子资产 = 证券资产 + 与同一赎回日匹配的现金差额 + 其他明确对价
单位估值 = 总篮子资产 ÷ 最小申赎单位份额
```

- `预估现金部分/EstimatedCashComponent` 只是在 T 日可用的临时输入。
- `现金差额/CashComponent/PreCashComponent` 只在后续 PCF 明确对应同一个赎回日时，才能替换预估值。
- 不得把当天的预估现金与另一个交易日的实际现金差额拼接为“实际总篮子资产”。
- 若只研究证券价格或 XOP 对冲比率，使用“证券资产”；若研究最终赎回回款，使用“总篮子资产”。

### 汇率分层

| 场景 | 可用汇率 | 定位 |
| --- | --- | --- |
| 招募书/PCF 的基金估值 | 人民币中间价或招募书允许的估值汇率 | 基金会计与 PCF 公式口径 |
| 中国盘中实时监控 | 当时已发布的中国外汇交易中心参考价/最新可用市场数据 | 交易信号，非最终结算承诺 |
| 事后赎回回款复核 | T 日人民币外汇交易中心官方收盘价（若实际账务验证采用） | 结算回测；须按基金逐笔验证 |

“招募书允许中国外汇交易中心收盘价”不等于“所有实际赎回必然使用该价格”。文件会明确区分合同规定、PCF 计算口径和已验证的实务口径。

## 自动化接入最低字段

每个方案至少应能向程序提供以下字段：

- 标的代码、交易所、分类、招募书版本与原始 URL；
- `TradingDay`、`PreTradingDay`、最小申赎单位、申购/赎回开关及限额；
- `EstimateCashComponent` 与后续同一 T 日的实际现金差额字段；
- 成分证券代码、数量、现金替代标志、替代金额及市场；
- 实时估值价格源、实时汇率源、最终结算汇率源；
- 对冲代理、滚动 beta/对冲股数、开仓与平仓的可执行 Bid/Ask 规则；
- 现金差额、现金替代款的合同时间窗与实际到账观察值。

## 更新触发条件

- 基金公司发布新的招募说明书、基金合同或申赎公告；
- PCF 的最小申赎单位、成分数量、现金替代标志、限额或申赎模式变化；
- 实际到账显示汇率、现金差额或到账时间与既有假设不一致；
- 对冲代理的成分重合、可借性、Bid/Ask 流动性或 beta 显著变化。

本目录记录方法与证据，不构成交易指令；实际下单前仍须检查当日 PCF、申赎状态、借券、限额和可成交报价。
