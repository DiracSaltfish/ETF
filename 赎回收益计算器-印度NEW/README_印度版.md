# 164824 印度基金赎回收益计算器

当前启动入口是 `india_ui.py`，启动脚本已切换为本文件夹下的印度版程序。原有 XOP/159518 文件保留在目录中，作为历史参考，不再参与印度版主计算链路。

界面以迭代前 XOP/159518 版本为基线，继续使用原来的顶部工具栏、概览卡片、横向标签页、表格样式、字体和配色；印度业务只替换标签含义、数据源与计算链路，不另起一套页面风格。

## 已实现规则

- 自动扫描 `持仓快照根目录/YYYYMMDD/chicang1.csv`、`chicang2.csv`、`chicang3.csv`，QMT1、QMT2、QMT3 独立计算；成交明细仅用于 FIFO 成本，可留空。
- 当日可赎量取赎回日前 3 个中国基金交易日日终持仓的最小值；任一快照缺失即标记 `blocked`。手工赎回先形成预留，新日终快照到达后自动对账解除预留。
- 内置 2025、2026 年深交所官方休市安排，并可叠加基金暂停开放日；缺少目标年份官方日历时阻止计算。
- 手工登记赎回，或导入包含赎回行的 164824 交割单。导入先预览，确认后写入 `data/india_redemption.sqlite3`，重复导入按事件 ID 幂等。
- 每 270,000 份生成一个标准篮子；不足一个标准篮子的零碎份额保留为残差，不自动虚构 NIFTY/INDA 对冲数量。
- 结算日期按赎回日 T+5 交割单、T+6 资金可用计算；没有 PCF、现金差额或现金替代退款模型。
- 有实际净赎回款时直接使用净额，不再次扣赎回费；只有净值或毛额时才按可配置费率估算。`0.464%` 默认标记为待首张实单确认。
- IB Flex CSV 按表头标准化 NIFTY 和 INDA；只有带 `INDIA_` 前缀 `orderRef` 的成交才允许进入篮子，其他成交隔离并提示人工映射，避免混入其他 NIFTY 策略。
- NIFTY 按每月最后一个星期二起切换下月合约；订单计划保存美东和北京时间，自动处理夏令时。
- 换仓预览顺序为同一时间先 BUY NIFTY、成交后 SELL INDA；平仓为美东 11:30 BUY 364 股、15:59 BUY 606 股。实际数量不是 970 时按比例分配并保持数量守恒。
- 订单模块先生成预览并持久化计划；`live_enabled` 默认关闭。只有在数据源设置中显式开启实盘总开关、连接TWS、勾选订单、解锁实盘并输入 `SEND` 后才会发送。
- 换仓按父子附加单发送：NIFTY BUY 是带时间条件的父单，INDA SELL 子单只在父单完全成交后激活；两段INDA平仓发送前会核对TWS实际空头，数量不足时阻止可能的反向开多。
- TWS 的 queued、submitted、openOrder、orderStatus、execDetails 和 commissionReport 会保存到本地主账；已提交的 `INDIA_ orderRef` 跨程序重启禁止重复发送。
- 连接TWS时会同时同步未完成单和可读取的已完成单；订单页支持勾选已提交订单后发起撤单，并等待TWS的 `Cancelled` 最终回报。已撤订单重新生成时自动使用 `_R2`、`_R3` 修订号，不覆盖历史订单。
- 实盘发送逐项核验TWS返回的 conId、品种、币种、NIFTY本地合约代码、合约月和乘数；任一不符整批阻断。
- 内置2026年NYSE休市日，并阻断11月27日、12月24日13:00提前收盘后触发的INDA条件单；缺少目标年份日历时拒绝实盘发送。
- 交割单账户缺失或不是QMT1/2/3时不再静默归入QMT1；问题行进入导入异常。赎回登记页可删除误录记录并立即释放预留。

## 使用

```bash
conda run -n ag python india_ui.py
```

默认持仓目录为 `/Users/ellis/Desktop/交易表格`。点击“刷新可赎量 / 重算”即可读取三个账户；如需计算国内 FIFO 成本，再选择 QMT1/QMT2/QMT3 成交明细。手工赎回会校验最终可赎量，超额时拒绝写入；交割单导入必须在预览后确认。

## 测试

```bash
python -m pytest -q -p no:cacheprovider
```

实际 164824 交割单尚未提供前，程序不会猜测未知字段，也不会把任意资金流水当成净赎回款。首张实单到达后，重点校准业务名称、赎回费、T+5/T+6 实际日期和净款字段。
