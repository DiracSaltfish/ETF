# IBKR 篮子管理

面向 XOP 与成分券多空底仓的 PyQt 桌面工具。程序保留原来的篮子建仓/手动下单功能，并新增独立的 **Close Only（仅平仓到 0）** 流程。

## 推荐的平仓流程

当前目标形态是：

- 成分券只能 `BUY`，且买入数量不得超过该券当前空头数量；目标不低于 0、不穿越为多头。
- XOP 只能 `SELL`，且卖出数量不得超过当前 XOP 多头；目标不低于 0、不穿越为空头。
- 支持 `5% / 10% / 25% / 50% / 100%` 分批释放。
- XOP 不简单按选定百分比机械卖出。程序用第一次确认时固定下来的成分券参考价格和初始 XOP 数量计算剩余配比，并且只按已经观察到的成分券成交结果收紧 XOP 卖出量。

操作顺序：

1. 在“仅平仓到 0”区域选择本批比例和定价方式。
2. 点击“生成/刷新预览”。该步骤使用只读连接，不会下单。
3. 在“平仓到 0 预览”页逐行检查账户、conId、当前持仓、方向、数量和预计持仓。
4. 通过计划确认、账户口令和最终确认后执行。
5. 等本批所有活动订单成交或撤销并刷新状态，再生成下一批预览。

不要从订单监控页直接补发 Close Only 订单。任何残量都必须通过新的持仓和活动订单预检重新计算。

## Close Only 安全边界

首单之前会重新读取 TWS，并要求批准计划与实时状态完全一致。以下任一情况都会阻止执行：

- 未明确选择账户，或计划账户与 TWS 账户不一致；
- 篮子范围内存在任何活动订单，包括 `PendingCancel`；
- 同一代码存在多条合约持仓、conId 不一致、非 `STK/USD` 合约或碎股；
- 成分券已经为多头，或 XOP 已经为空头；
- 持仓超过本次平仓会话的初始仓位，疑似发生外部加仓；
- 篮子文件在原路径被改成不同成分范围；
- 本地会话文件损坏或格式无法识别；
- 设置启用了 Outside RTH。
- 通用 TIF 不是 `DAY`（Close Only 禁止把未完成订单以 GTC 带到下一交易日）。

提交过程中，每一笔订单前还会再次检查活动订单、实时持仓、方向、conId 和可平数量。后续持仓缩小会自动收紧该笔数量；发现新的活动订单、持仓扩张或方向穿越则立即暂停，不再发送后续订单。

程序会先提交成分券腿，再按已观察到的成分券成交结果计算 XOP 可卖数量。若发生中途异常，已经捕获的订单会返回监控表，流程状态变为 `PAUSED`；不要直接重试，应先核对 TWS 的真实订单和持仓。

## 会话和审计

第一次执行会在程序目录生成 `close_only_sessions.json`，保存：

- 固定的初始持仓、conId、参考价格和篮子范围；
- 计划 ID、批准指纹、订单意图、orderRef、orderId 和 permId；
- `CONFIRMED / SUBMITTING / WORKING / RECONCILING / PAUSED / COMPLETE` 状态事件。

该文件用于跨重启保持同一套固定计算口径，不应手工编辑或删除。若文件损坏，程序会失败关闭并禁止重新创建平仓会话。

## 原有功能

界面仍保留：

- 按目标 XOP 股数折算成分券目标并买入/卖出补差；
- XOP 手动单票下单；
- TWS 持仓、券源和订单状态监控。

这些是独立的通用下单功能，不具备 Close Only 的方向硬限制。释放现有中性底仓时应使用“仅平仓到 0”入口。
一旦生成了有效 Close Only 预览或存在未完成 Close Only 会话，旧的成分券建仓和 XOP 手动下单按钮会被锁定，避免两套流程互相改动仓位。

## 文件结构

- `close_only.py`：纯计算、固定会话基准、计划签名和持仓边界。
- `close_store.py`：本地会话与订单审计的原子写入。
- `ib_service.py`：只读预览、实时二次预检和有界提交。
- `ui.py`：预览表、账户口令、执行结果和监控交互。
- `tests/`：纯计算与模拟 IB 执行测试；不会连接 TWS 或真实发单。
